# 数据目录占用与世界导入

给改写盘代码、目录切换、实例复制/删除、世界导入的人看：同一数据目录只允许一个启动器窗口；怎么区分"目录被占用"和"文件被占用"；新增写入口要遵守什么；破坏性操作的拒绝顺序。

## 1. 同目录单窗口

产品启动时，在主窗口和日志文件建立前取得当前游戏目录及自带回退目录的锁（`src/util/DirectorySessionLock.hpp`）。同一目录已被另一份启动器占用时提示并退出；锁创建失败也不继续写入。切换游戏目录、删除目录、复制实例到其它游戏目录时同样先取锁。

- 锁文件在系统临时目录，用解析路径别名和 junction 后的路径哈希命名，不往游戏目录里放锁文件。
- 活进程的锁不因时间过长而失效：Qt 判陈旧的第一道是"那个 PID 还在且进程名对得上"，优先于时间。异常退出（崩溃、任务管理器结束、断电）留下的锁靠 `QLockFile` 过期时间接管，**该值必须大于 0**：`staleLockTime == 0` 时 Qt 的 `isApparentlyStale()` 永不判陈旧，死 PID 的锁会一直锁死目录（2026-11-04 修正，修前一台机器上积了 6 个）。现取 60 秒，崩溃后用户最多等一分钟，不会误伤运行中的那一份。
- 拿不到锁时提示带**锁文件完整路径**并说"确认没有别的窗口在运行就删掉它"（文件名是 SHA-256，不指路用户只能重装）。不要手工删除另一份仍在运行的启动器的锁。
- 本进程取得的锁保留到退出，切换目录不立即释放：旧目录仍可能有后台任务或游戏会话。不同启动器副本、互不重叠的数据目录可分别运行。锁不约束游戏、同步软件或外部编辑器。

## 2. 共用同一棵全局设置

装在两个目录的启动器各有数据目录，但 `HKCU\Software\WTFML\WTFML` 按机器共用。整份写回会交错覆盖（谁后保存，谁把对方刚改的项打回旧值），所以设置层逐项写：

- `LauncherSettings::save()` / `GlobalJavaSettings::save()` 只写与 `load()` 快照不同的项；一项没改就一个字节不写。因此未改过的默认值不会在首次保存时覆盖其它窗口，其它窗口删除某项恢复默认后，本窗口保存别的项也不会把它复活。写入失败（`QSettings::status()` 不是 `NoError`）不推进"已保存"基线，下次保存重试。
- 账号当前身份（`Account/…CurrentUuid`）、令牌和工具箱几项各写自己那一格，没有整份盖回去的形状。
- 主题 `Theme::save()` 同样逐项：`load()` 记下盘上原值和含默认值的语义基线（连同配置文件身份），`save()` 只写不同的项；"上次设过、这次没设"的项照样删（不删则改回默认、重开又复活），但只删**盘上仍是当初看到的那个值**的项；**未知（未来版本）主题键保留**。写入失败不推进基线；没有基线（进程未 `load()` 或换了配置文件）时退回整组清掉重写。
- 限制：只保证互不相干的项不互相打回；两个进程**同一项**并发修改仍是后写者赢。

## 3. 真实双进程验收

`tools/acceptance_directory_boundary.py` 是人工验收入口（不进 CTest），需要真实 Windows 桌面。它启动两份真实产品进程（不同 exe 目录、共用同一份 `HKCU\Software\WTFML` 与同一数据根），验证第二个进程停在「启动器已在运行或目录不可用」对话框、不创建主窗口、不截断 `logs/wtfml.log`，关掉对话框后以 1 退出；第一份窗口始终存活，最后正常关窗。脚本运行前拒绝已有启动器进程，并把标题临时钉回产品默认；结束时恢复借用的 `Launcher/CurrentFolder` / `Launcher/TitleText` 并清理临时安装目录。

2026-10-24 实跑（Release、Qt 6.10.1）：10/10 断言通过。用法见 [TESTING.md](../dev/TESTING.md) 的人工验收探针一节。

## 4. 「目录被占用」与「文件被占用」

界面上必须说清是哪一条，处理完全不同：

| | 目录被占用 | 文件被占用 |
| --- | --- | --- |
| 含义 | 另一份启动器已持有该数据目录的生命周期锁 | 目录锁是我们的，但某个文件被游戏、同步盘或杀毒软件开着（Windows 共享冲突） |
| 症状 | 提示「这个数据目录已被另一份启动器占用，请先关闭那一份窗口。」整个启动器不该继续写这个目录 | 单个操作失败（改名、删除、发布备份、写配置），提示指向那个文件或操作，如「文件被游戏占着」 |
| 用户该做 | 关闭另一窗口或切换游戏目录 | 退出游戏/同步程序后重试，无需关闭启动器 |

不要合并成「目录正被使用」：会让用户关掉两份启动器后仍不知道是游戏还开着；反过来把文件冲突说成"另一份启动器占用"会让用户去关一个不存在的窗口。删除世界这类无法回头的操作照实报失败，不假装成功。

**判据（2026-10-24 起）**：
- `ZJ6`：夹具用 `dwShareMode = 0` 的 Win32 句柄拿住树里一件文件（等价于游戏还开着），验世界改名/导入失败时旧的一份原样在、新名字没被造出来、导入暂存收拾干净。
- `ZAO6`：整棵进回收站时 `moveToRecycleBin()` 返回 `false` 并带原始 HRESULT，被占的那件还在原处、大小没变，放开后逐字节原样；放开后同一棵照常进去。
- 权限拒绝（文件 ACL 限制写入）：`ZJ7` 给 `saves/` 挂拒绝写/追加的 ACL（`icacls /deny …:(WD,AD)`，拒绝项压过允许项，管理员也绕不过），导入世界照实失败、不留半截、源一个字节不动，权限放开后同一趟成功。`ZJ8` 把拒绝项（`/deny …:(RD)`）挂到源里一件上，失败话术由 `copyTreeWithoutFollowingLinks()` 的首因点名那件与阶段（`文件复制失败` / `无法打开源或临时文件`），不发布、不留暂存。`ZAO7`：删除只需 `DELETE`，那件不许写也照样进回收站。
- `ZAP1` / `ZAP2`：「删除没有权限」本机造得出来，夹具挂两条拒绝项（该项 `(DE)` + 所在目录 `(DC)`）。Windows 判一项能否删是"自己有 `DELETE`"**或**"所在目录有 `FILE_DELETE_CHILD`"二者其一，只挂 `(DE)` 时父目录的 `DC` 仍在，照样删得掉；两条一起拒才挡得住。（2026-10-24 曾记"只能真机验"，已更正。）
- `moveToRecycleBin()` 动手前先 `CreateFileW(path, DELETE, …)` 预检：`ERROR_ACCESS_DENIED` 报「权限不允许删除」，`ERROR_SHARING_VIOLATION` 报「被别的程序占着」，不再混在「回收站不可用、放不下、或者被占着」一句里。预检让整个过程一个字节不动；让 `IFileOperation` 自己去撞会先把子树里删得动的搬进回收站、最后才在目录层失败（里面的文件没了、目录还在），`ZAP1` 钉的就是里面那件还在原处、内容没变。
- 树里有只读文件（`FILE_ATTRIBUTE_READONLY`，例如从只读介质拷来的整合包、被网盘标成只读的 jar）：`IFileOperation` 回 `COPYENGINE_E_ACCESS_DENIED_SRC`（0x80270021），整棵留在原地，用户看到的却是「回收站不可用 / 空间不足」。`moveToRecycleBin()` 这时摘掉子树里的只读位再试一次（资源管理器也是先问一句、再摘位、再删）；一次就成功的那趟一个属性都不碰，进回收站的那一份还是只读的。`ZAO2` 钉的是「只读文件不许让整棵留在原地」。

## 5. 写入口约定（2026-10-22 审计）

**规则**：写到「当前游戏数据根 / 启动器默认数据根 / `versions`、`servers` 所属根」里的用户数据，必须先过 `WriteDirectoryGuard::acquire()`（把路径归并到数据根）。`ServerWriteGuard` 与直接调 `DirectorySessionLock::acquire(AppPaths::minecraftDir())` 用同一把键，算等价。

审计覆盖 `src/` 下所有 `QSaveFile` / `QIODevice::WriteOnly` / `QFile::copy` / `QDir().mkpath` / `QFile::rename` 的 54 个文件：

- **显式取锁 35 个**：实例复制/移动/删除/改名/元数据、导入、备份/还原/中断恢复、版本与文件修复、服务端注册/配置/玩家名单/EULA、预设库与预设应用/提取/模组安装、世界导入/移动/`level.dat`、升级事务、任务/启动历史账本、实例分组、服务器列表、更新策略、Java 别名目录、启动日志等。
- **不取锁 17 个**：用户自选导出路径（整合包、日志、崩溃报告、主题、哈希清单）、可重建缓存（图标、皮肤缓存、默认皮肤、服务器状态、主题背景、预览资源）、诊断日志。写的是丢了可重新生成的东西，或不在数据目录里。
- **审计补上的 2 个缺口**：`GlobalJavaSettings::downloadJavaRuntime()` 与 `downloadJavaFromMojang()`（建目录、解压运行时前取根锁，拿不到不写）；`PresetApply::makeBackupDir()`（备份落在预设库那头，单独取锁，拿不到整趟停下）。

只由已取锁调用方驱动的写函数（`LocalFileReuse`、`ResumableDownload`、`ZipUtil`、`DataPackPreset`、`GenericFiles`、`MalilibKeys`、`ServerListPreset`、`FolderManager::copyTreeWithoutFollowingLinks`）按调用方记账：**新增调用方必须自己先取锁**。限制：审计只看"写入口有没有取锁"，路径边界见下节。

## 6. 路径边界（2026-10-24 复核）

问的是"这条路径最终落到哪儿、中间经过哪儿"，分三层，各只有一个出处：

1. **名字那一段**：用户输入或清单里的名字拼路径时逐段过 `InstanceFiles::validatePathSegment()`（分隔符、`<>:"|?*`、控制字符、`.`/`..`、结尾点与空格、Windows 保留设备名）。整合包里的相对路径走 `ModpackImport::isSafeRelativePath()`，内部也是它。
2. **最终落到哪儿**：`InstanceFiles::pathIsSameOrInside()`（解符号链接、8.3 短名、大小写，再解 junction）。实例复制/移动、世界导入、升级事务、备份还原、暂存目录、目录锁键都用它。
3. **中间经过哪儿**：`InstanceFiles::pathHasLinkComponent()`。末级文件自身虽非链接，但其上级路径（如 `config/`）可能指向外部目录。四个写入口用它：MultiMC patches、跨实例传输、数据包预设、MaLiLib 热键。

数据根**里面**由用户自己摆的 junction（`mods` 指到另一个盘、`config` 指到共享目录）予以保留；安全防护重点拦截跨越实例根边界的路径逃逸，与源侧链接不跟随规则保持一致。

测试：`ZJ3`/`ZJ5`（锁键别名、复制实例）、`TR5`（传输不跟 junction）、`PD7`（通用文件源侧链接）、`PF10`（MaLiLib：`config` 是 junction 时读要说清楚、写一格不穿透、链接那头一个字节不动）、`PL10`（数据包：`saves/<世界>/datapacks` 是 junction ⇒ 拒绝，也不改落到 `datapacks-pending/`）、`MultiMC`（`<数据根>/libraries` 是 junction ⇒ 拒绝，链接那头收不到东西）。

## 7. 复制实例：先暂存，再发布

`VersionManager::copyInstanceFrom()` 先把整棵树落到同卷的 `versions/.wtfml-staging/<uuid>`，jar / json / `wtfml.meta` 在暂存里改好，最后一次改名发布。原因：拷几 GB 要几分钟，期间用户或另一份启动器可能在目标名下放了东西，直接拷到 `versions/<新名字>` 的旧写法失败时按 `destDir` 清理，会连对方刚写的一起删。

- 失败只清本次自己的暂存，目标位置一个字节不碰，半成品不进实例列表。
- 发布前重新检查目标名字；已被占用就失败并清暂存，不覆盖、不删对方目录。
- 暂存层没有顶层 jar / json，`installedVersions()` 不会把它当实例。暂存父目录若是 junction / symlink 直接拒绝（同"源侧链接不跟随"）。
- 判据 `ZJ5`：正常复制后暂存层收掉；源里有 junction 时失败且不发布；拷树期间另一份创建同名目录时发布失败、用户文件原样、暂存清掉。

## 8. 破坏性操作交互矩阵

同一实例的删除、快照、备份、还原、复制/迁移与文件页改动，按"先拒绝、再重检、最后才动盘"排：

| 同时发生的事 | 拒绝/重检方式 | 回归位置 |
| --- | --- | --- |
| 游戏正在运行 | 删除、世界备份/还原、快照、还原实例、文件页启用/禁用/删除都先问运行状态；关窗另有确认 | T35、T43、T20.10 |
| 另一项文件操作在跑 | 控制器 `busy()` + `installingVersionIds()`；文件页宿主回调拒绝；批量文件页操作登记实例；快照确认框关闭后重检；世界备份开始前拒绝 | T35.2b、T20.10、T20.10b、ZJ5 |
| 外部程序改了文件 | 备份冻结字节后重扫清单；还原发布前重扫目标；不一致就停在发布前 | ZQ4、ZQ8、ZQ10 |
| 磁盘空间不足 | 备份/还原先算空间；升级有 `spaceBudgetBytes`；不足时不动盘 | ZQ8、InstanceUpgradeChecks |
| 权限/只读失败 | 删除先摘只读位再试；写入失败如实报错 | ZAN1、ZAN2、ZQ4 |
| 改名失败/目标被占用 | 复制先暂存，发布改名失败只清暂存；替换目标前再次检查 | ZJ5、PL10 |
| 关键发布阶段中断 | 备份/还原/升级/数据包替换都有登记或活动锁，恢复只处理能对上归属的现场 | ZQ10、ZQ11、PL10、InstanceUpgradeChecks |

未覆盖：真实慢盘、杀毒实时扫描和发布机双窗口，需按 [TESTING.md](../dev/TESTING.md) 的人工探针复跑。

## 9. 世界导入

存档页导入在后台复制，目标实例完成前不能启动或处理其它文件操作；页面可关闭，完成回调不访问已销毁的页面。

- 文件先写入 saves 内独立暂存目录，完成后才改名为正式世界；已有同名世界绝不覆盖。隐藏文件保留，源链接拒绝跟随，源世界不删除。失败清理本次暂存，清理失败时说明位置。
- 后台复制每 1 MiB 检查停止条件，整项预算 600 秒；关闭控制器时请求停止。
- 任务中心的「取消」协作式停下，没拷完的暂存被清理，账本记「已取消」而非失败、不弹失败提示；取消晚于发布则报成功（存档已在那儿）。
- 注意：导入过程为常规逐文件复制，导入期间外部程序不得修改源世界数据。

## 10. 世界删除

用户在确认框点「删除」后，整棵目录树才在工作线程里删（junction / 符号链接不跟随）；删除期间该实例记进「文件操作中」，不能启动或做其它文件操作，页面可关闭，完成回调不访问已销毁的页面。删除不提供取消：停在一半留下半截世界，比删完更难收拾。删不干净照实报失败（原话仍指向"多半是被游戏占着"），不替用户清理剩下的内容。

## 11. 创建备份时关闭窗口

创建世界备份和实例快照把关闭取消传给目录扫描、分块哈希和打包进程。打包等待每 100 ms 检查停止条件，停止子进程后清理本次不完整归档，不删已有归档。控制器发起的创建备份和还原整项预算均 600 秒。文件系统读取是协作式取消，故障磁盘的系统调用不保证立即返回。还原的停止条件**只在挪走「现在这一份」之前**生效（读清单、空间检查、安全快照这一步；刚做的安全快照会删掉）；一旦开始替换目录就必须走完，停在那儿会让用户既没有旧的也没有新的。不强杀线程。
