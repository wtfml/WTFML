# 实例版本升级

给改实例升级链路（`ui/InstanceUpgradePage`、`InstanceUpdateFlow`、`operations/Upgrade*`、`InstanceUpgrade`）的人看：现行行为、数据保护规则、尚未完成的部分。真机验收清单见 [UPGRADE_ACCEPTANCE.md](UPGRADE_ACCEPTANCE.md)。

# 一、现行行为

## 1. 入口与流程

入口在单个实例设置的「维护」页最上面：`ui/InstanceUpgradePage`（接线在 `src/controllers/InstanceUpdateFlow.cpp`）。当前实例始终是来源，不再选来源目录。`ui/InstanceUpdateWizard`（QWizard，四步）仍在，但已降为后台执行骨架：检查表、确认页和执行页都挂在它上面，旧的「打开实例更新向导…」按钮已隐藏；页面「预览并确认」在页面闸门通过后直接走"准备 + 执行"，只有这条路当前不可点时才退回弹出向导（`updateWizardRequested` 信号仍连着）。

页面（只画状态、只发信号，判断都在 `operations/UpgradePageState` 等纯逻辑层）：
1. 来源/目标双栏。目标选 Minecraft 版本、加载器及具体加载器版本，默认创建副本并起新名字。稳定加载器版本作默认建议，没有稳定版本时需明确选测试版，获取失败可刷新。
2. 「兼容性报告…」：有评估结果时打开 `ui/UpgradeReportDialog`，没有结果时提示"还没有检查结果"。报告分五组（正常/无法确认/检查失败/不兼容/缺前置），只有正常项默认折叠；可按名字或依据搜索、只看某组、显示/折叠正常项；组标题带条数，必要项未处理有摘要。检查就绪后页面记下报告指纹。
3. 九类选择（§7）和每行"多少个 / 多大"（来源只读扫描一次）。
4. 「更新记录…」打开 `ui/UpgradeHistoryDialog`（§8）。
5. 底部摘要与「预览并确认」。闸门 `firstBlocker()` 四道：来源/目标/实例名（空、重名、与来源同名）、报告过期（目标或选择一变，旧检查按指纹判过期）、占用、勾了 Mod 配置却没勾 Mod 文件（`ConfigWithoutMods`）。来源实例此刻在跑或被别的作业占用，页面提前提示。整合包带自定义启动配置（主类不是 `net.minecraft.client.main.Main` / `net.minecraft.launchwrapper.Launch` / `cpw.mods.bootstraplauncher.BootstrapLauncher` / `net.fabricmc.loader.impl.launch.knot.KnotClient`，如 lwjgl3ify）时先提醒一次：升级后启动配置可能对不上。
6. 有"必须逐项选择"的模组，预览确认时按最保守的「禁用，保留文件」先填上，确认框仍列出这些项。

执行阶段（向导的模组检查、确认、执行页）：
- 模组表每行选「保留启用」或「禁用，保留文件」：本地声明符合默认保留，明确不支持默认禁用；未知/未检查必须明确选择，也可批量处理未确认项。平台查询可停止，停止/失败不说成"没有适配版"。刷新结果不覆盖用户的明确选择。
- 创建更新副本（默认，另起名字）或更新当前实例，核对保留/禁用数量；两者都保留全部普通用户文件。
- 开始后由现有下载器自动准备独立命名的核心/加载器，再继续副本或原地更新，不跳下载页、不手动安装。核心准备可由任务中心取消，准备阶段有 900 秒看门狗；失败只留下可检查的准备目录，不修改原实例。关闭设置页会停止后续串联。准备目录名以 `wtfml-update-` 开头，可能成为安装器继承链的一部分，不自动清理。
- 执行页显示任务阶段和最终结果。核心事务仍做完整校验和执行前确认；提问显示在向导内。文件事务执行中不允许关闭，核心准备可取消。整趟更新在任务中心**只有一个父任务**（准备核心/复制/校验/发布是它的步骤），取消收成 Cancelled、失败收成 Failed，都不显示成成功。
- 创建副本：源实例保持不动，只复制一次候选目录、逐文件完整校验后换核心并发布；**不为副本另做整份 ZIP 快照**（源实例本身就是回滚材料），占用约一份实例体积。
- 不能开始更新：只输入搜索文字、没有选中有效条目，或本地模组仍在读取/平台查询进行中/还有未确认项。收起的下拉框不响应滚轮；模组列表独立滚动，不用整页嵌套滚动。

## 2. 适配模组替换（2.1.3）

对**平台明确给出目标发行版**的模组，逐文件表在「保留启用 / 禁用，保留文件」外增加「替换为平台适配版 <版本>」：

- 同时满足才给出这一档：发行版的游戏版本与加载器命中目标、主文件有安全的 http(s) 地址、文件名是单个 `.jar`、大小与 40 位 SHA-1 齐全；缺一项退回未知状态，需用户显式选择确认。
- 已知目标版本的默认选择是替换（逐项可见），可改回保留启用；未知、声明不支持、本地明确排除的项仍必须逐项选择，不自动替换。
- 嵌套 JAR 不单独成项，**随父 JAR 一起替换**。扫描对每个 JAR 的嵌套条目做有界枚举（最多 200 个 JAR / 10 秒），超出明确标"未完整枚举"。
- 执行前：下载并校验平台适配文件（复用 `ModInstallPlan`、预设安装器的依赖/冲突解析、`DownloadManager` 与落盘哈希校验，不另写下载器），必要前置自动补齐；随后把**实际**要替换/新增的文件列在确认框里，取消则整趟不执行。
- 替换失败、任一前置失败、下载/哈希校验失败或预览与实际版本不一致：**整趟回滚**，源实例/原目录一个字节不动；同时写统一 `OperationReport`（kind `mod-replacement`）和 `<报告>.failure.txt`，点名失败文件与原因。可选前置失败也按"整趟回滚"处理，逐项列出。
- 成功后在实例目录写 `wtfml.update-changes.json`（格式 `wtfml-update-changes/1`，保留最近 20 趟），记录核心变更、逐项 `replace`/`add`、项目与发行版、旧/新版本、SHA-1 和"嵌套 JAR 随父替换"的说明；它属于事务候选，发布校验通过才算成功。
- 下载暂存只落 `cache/operation-staging/<uuid>`，成功/失败都清掉；失败报告可在任务详情和启动器日志里找到路径。重新执行请重新打开检查，不复用旧确认。

## 3. 声明覆盖扩展（2.1.4）

- **Quilt**：作为目标加载器可在安装页选择，也可通过实例更新和整合包导入准备/升级（meta `v3/versions/loader/<mc>` 的 profile + 库，与 Fabric 同一条路径，没有启动器安装器进程）。Quilt 目标下，有 `quilt.mod.json` 的模组按 `depends[minecraft]`、`depends[quilt_loader]`、`depends[java]` 检查；只有 `fabric.mod.json` 的按 Fabric 声明检查（Quilt 能加载 Fabric 模组），但不拿 fabricloader 范围去卡 Quilt 加载器版本。
- **旧 Forge**：先读 `mcmod.info` 的 `acceptedMinecraftVersions`；没有现代声明时读 class 常量池里的 `@Mod` 注解（有界：每 JAR 最多 3 个 class、整轮预算）。读不动、没有范围或被预算截断一律记**未知**，逐项强制选择，原因写进行内依据和日志。
- **加载器具体版本**：声明里带 `fabricloader` / `forge` / `neoforge` / `quilt_loader` 范围时与目标加载器版本比较；不满足标"加载器版本不满足"，读不动记未知。
- **Java**：声明里带 `java` 范围时与**当前配置的 Java 主版本**比较（向导打开时探测一次，不拿游戏最低要求代替）；不满足标"需要 Java …"，读不动/探测不到记未知。
- **嵌套 JAR 声明**：在"随父 JAR 替换"之外，有界读取嵌套 JAR 自己的声明并检查 Minecraft 范围；解析失败/超限记未知并强制选择。嵌套仍不单独替换。
- 三种结论严格分开：**读到且不匹配**（可默认禁用）、**读到但无法解析**（未知，强制选择）、**没读到/没声明**（未知，强制选择）。平台有适配版也不能把未知项默认成替换。未知项原因出现在确认页"文件变更"文本、启动器日志和任务详情里。

## 4. 两种模组判断分开显示

- 平台：有目标发行版、未找到目标发行版、查询失败、元数据不足、身份未知。
- 本地文件：Minecraft 声明符合、不支持、明确排除目标版本、无法确定。

因此可出现「平台未找到目标发行版；本地 Minecraft 声明符合」：依据现有文件内置声明判定保留，区别于跳过或替换适配版。网络失败保留未知状态，不判定为无适配版。

- 已识别身份从现有识别缓存或预设安装记录读取，并与实际 JAR 的 SHA-1 核对，不按文件名猜项目。
- 每个页面用独立网络请求器，目标切换取消旧查询，旧回调不能覆盖当前目标。平台查询用 Qt 异步网络，最多 4 路并发，180 秒总预算；暂时失败最多重试一次，401/403/404/429 不反复重试。目标切换/停止清除全部在途钥匙，旧结果不可回写。
- CurseForge 查询失败后，可用已校验本地 JAR 的 SHA-1 向 Modrinth 核验文件身份，匹配后才查后备项目；不凭名称、slug 或相似搜索换平台，不改写原识别缓存。界面标注 Modrinth 后备；双边失败仍是未知。失败原因与项目 ID 写启动器日志，不记 API key。2026-10-21 本机只读实测：默认 CurseForge 镜像对项目 547434 的 26.2/Fabric 请求返回 HTTP 503，Modrinth 同项目返回 200（仅此次实测）。
- 结果更新保留列表滚动位置，可用「重新检查」刷新本地文件和平台结果。平台有目标发行版且本地声明符合的条目放在列表末尾的「正常兼容」分组，默认折叠；失败、未知、无目标发行版、声明冲突优先展开。刷新保持展开状态，折叠不影响逐文件选择或计数。

## 5. 本地声明的覆盖范围

- Fabric：`fabric.mod.json` 的 `depends.minecraft`，同时检查 `breaks.minecraft`。
- Forge / NeoForge：`META-INF/mods.toml` / `META-INF/neoforge.mods.toml` 的 Minecraft 必要依赖范围。
- 支持常见数字版本、比较运算、通配、tilde/caret、数组或关系和单个 Maven 区间。Fabric 单独按扩展语义版本解析，支持空预发布下界（如 `~26.2-`）、预发布比较及重复尾部通配符，不把 Maven 或 npm 的 caret 规则混入 Fabric。无法解析的范围、多个不同 Minecraft 范围保留未知。
- 声明通过一个子进程批量只读获取：每条最多 1 MiB、整批正文最多 16 MiB、最多 10000 个 JAR、整批 60 秒超时；部分失败保留此前结果。平台身份核验另有 120 秒预算，声明失败不跳过已有身份。超预算部分明确显示未检查。
- 限制：「Minecraft 声明符合」仅核验版本号匹配；加载器版本、Java 运行时、前置依赖及 Mod 冲突仍需运行时验证。平台检查本身不写盘；替换操作在用户确认后执行，必要前置按 `ModInstallPlan` 补齐。当前不含全局依赖求解能力。

## 6. 原地升级与回滚的数据保护

原地升级只替换合并后的核心配置与客户端 JAR，不复制目标实例的存档、模组或配置。逐文件保留清单用表格确认；未列入的启用 JAR 默认禁用，不删文件。兼容旧调用入口仍询问整体禁用或保持原状。操作前保存设置；替换完成后关闭旧设置页，防止旧控件回写。准备和校验在后台，相关实例在任务完成前不能启动或修改。

- **阶段**：原地升级的任务中心显示准备、完整快照、快照验证、保留原目录、发布、校验、完成；副本模式是准备核心、复制并校验副本、替换并发布、完成（没有 ZIP 快照两步）。
- **快照**：包括实例内 assets、libraries 及全部普通用户文件，不沿用普通快照的排除规则；先解压到独立临时目录，逐文件比较路径、大小与 SHA-1，原文件变化也阻止发布。符号链接、junction、不可读文件、空间不足或无法确认空间充足时拒绝升级。
- **拒绝条件**：其它实例通过 `inheritsFrom`、jar 或目录链接引用当前核心时，拒绝原地替换和手动回滚。目录名就是原版版本号的共享基础实例不能直接原地升级，应先复制成自定义名称的独立实例。
- **空间**：原地升级需要快照 + 校验解压，估算保守（约两倍实例体积）；副本模式复制一次候选目录并读一遍校验，约一份实例体积。
- **回滚**：快照验证成功后才移动原目录；发布或校验失败时尝试恢复，恢复也另行保留当前版本，不直接删除。恢复材料在当前游戏目录：
  - `cache/backups/instances/`：升级前完整 ZIP，可由现有快照恢复入口使用；
  - `cache/instance-upgrades/<事务编号>/journal.json`：持久化阶段记录，不要手动编辑；
  - 同事务的 `original/`：可回滚的原目录；
  - 同事务的 `replaced/`：回滚时保留的升级后目录（含更新后的存档进度）。
  回滚不合并存档进度，所需新进度可从 `replaced` 取回。启动时检查当前游戏目录里未完成的事务，尝试恢复中断前的原实例；已成功提交的升级不自动回滚；恢复材料不自动清理。
- **副本模式没有"原地回滚"**：源实例从头到尾没被改，删掉副本即可；失败或取消时未发布的候选暂存由启动恢复或失败收尾清掉（只认本模块的 UUID 暂存目录）。
- **游戏目录改名/迁移后的事务重定位（2.1.5a）**：journal 记录 `rootFingerprint`（由事务编号、实例名、快照文件名和原始文件指纹算出）与 `rootRelative`/`rootName`。启动时扫描**已配置的游戏根**（文件夹列表 + 当前根，不全盘搜索），在候选根里发现事务后用事务自带材料重算指纹，匹配才恢复，不匹配不动盘并提示用完整 ZIP 快照恢复。恢复成功后 journal 里的快照绝对路径若随根迁移，改写为新根下的同名快照；不自动删除未知目录。
- 限制：原地替换阶段不提供中途暂停/取消。

## 7. 九类选择与选择性副本（2026-11-05 落地）

类别键（`operations/UpgradeSelection`，稳定键，含 `schematics`，存档内 `datapacks` 不单列）：

| 展示类别 | 键 | 内容与约束 |
| --- | --- | --- |
| 游戏存档 | `saves` | 有效用户目录下整个 `saves/`；世界内 `datapacks/` 随世界走 |
| Mod 文件 | `mods` | 按逐文件保留/禁用/替换和前置计划处理，含父 JAR 与嵌套内容关系 |
| Mod 配置 | `config` | `config/` 与 `defaultconfigs/` 同一展示类别（`defaultconfigs`→配置）；归属不能按 JAR 文件名猜 |
| 游戏设置 | `options` | `options.txt`；资源包启用列表与实际迁入文件共同决定，避免引用未迁入包 |
| 资源包 | `resourcepacks` | 文件、启用状态和优先顺序 |
| 光影包 | `shaderpacks` | 文件与可确认归属的相关设置 |
| 截图 | `screenshots` | 普通文件，默认不选 |
| 原理图 | `schematics`（`TransferPlanner` 的 `structure` 映射到它） | 默认不选；`structures/` 与 `schematics/` 按真实目录与文件类型去重，不混入 Replay |
| 服务器列表 | `servers` | `servers.dat`，复用现有读写保留策略 |

默认勾选：截图 / 原理图不勾，其余默认勾（盘上没有的执行时自动跳过）。选择指纹 = 来源/目标/已选键 → SHA-1。体积/文件数按选中的类别合计（日志/崩溃报告不入九类）；三条依赖提示。路径先过现有隔离/共享目录规则解析（不假定都在 `versions/<名字>/`）；账户、令牌、启动器缓存、其它实例、日志和未知外部链接不随类别迁入。

- **选择性复制**：`InstanceUpgrade::Request.copyRoots` 为空 = 整棵树（旧行为），非空只复制这些顶层路径，空间预算/校验/发布都按选中的那份算；页面勾选实时记到 `upgradeCopyRoots` 属性，经 `InstanceTransferController::upgradeToCopy(..., copyRoots)` 传入。`mw_check` 的 copy-roots 用例钉住"没选的类别一个字节都不进"。
- **options.txt 与资源包**（`operations/UpgradeOptions`，复制完 options.txt 后按它重写）：两边都有→搬源值；只有源有→默认不搬但列出；只有目标有→留目标值；资源包两行固定跳过，启用列表按"实际迁入的包"重建（vanilla 永远在前）。模组配置归属不按文件名猜：要么一起搬、要么别搬（`ConfigWithoutMods` 闸门）。

## 8. 升级历史

每个实例一份 `wtfml.upgrade-history.json`（`operations/UpgradeHistory`）：事务号、来源/目标身份与名字、前后版本与加载器、起止时间、成功/取消/失败原因、类别、复制/跳过/失败计数、`snapshotName`/`rollbackAvailable`；新的在前，最多 20 条，未知顶层键保留，读不懂拒绝写。副本/原地升级在收尾各写一条（目标一份；副本模式源实例也留一份，同一事务号）。记录弹窗 `ui/UpgradeHistoryDialog`：空态、时间/版本/结果三列，选中后显示事务号/来源/目标/类别/复制计数，并有「回滚上次原地升级…」。`journal.json` 主要记录目标实例与事务阶段，`wtfml.update-changes.json` 记录核心/模组变更明细，历史总览由 upgrade-history 维护。

**设计约束（后续实现必须遵守）**
- 新页面默认创建副本；现有原地升级和手动回滚继续保留。副本模式不额外强制生成 ZIP；原地模式必须先完整快照并校验后替换；用户另选额外快照时单独计入时间与空间。
- 平台适配文件和必要前置沿用现有下载链路与摘要校验；缺失必要项需前置处理，界面统一受安全规则约束。
- 目标选择必须含具体加载器版本并校验游戏/加载器组合，旧版本列表不能复用到另一个目标。
- 控制器保存目标游戏版本、加载器类型/具体版本、名称和类别集合；扫描/报告附带代次及来源指纹。目标或影响计划的类别变化立即撤销旧请求与旧最终确认，过期回调不能改当前页面。用户已确认的逐文件选择仅在同一有效上下文中保留，换目标后重新核对。
- 兼容报告中的平台结果、本地声明、依赖与运行保证分开；无网络、检查失败、没有发行版和明确不支持不合并为同一状态。
- 主页面只保留操作所需名称、值、数量和状态，长依据进报告/确认处，不使用中点分隔文案。桌面目标约 1000×750，窄窗和字体放大纵向重排、不能横向拖拽，底部动作保留，正文最后一项可完整滚到动作上方。
- **风险处理**：未识别模组先用内容指纹/本地声明核对，不按文件名或相似搜索替换。配置文件没有可靠的通用 Mod 归属表：能证明归属的按对应模组计划处理，其余列为归属不明，让用户明确选择复制或跳过。取消 Mod 类别而保留配置类别时要处理依赖关系，不能隐式下载模组或悄悄取消用户勾选。世界含模组数据，复制成功后仍需注意目标加载器/版本的兼容性，降级、跨加载器或关键模组缺失的风险在最终确认处显示，来源世界保持不变。核心/必要模组/摘要校验等关键步骤失败沿用整笔不发布的语义；**可选类别部分失败后是否允许发布需单独明确**，不能从"报告支持部分失败"推出允许发布半成品。
- **计划与执行**：只读计划至少含来源/目标身份及根、目标版本与加载器版本、类别键、逐文件来源/相对目标路径、操作类型、字节数、摘要/指纹、风险及用户选择。扫描、兼容查询、空间核对和最终确认共享这份上下文；磁盘可用量为预检估算，不进行文件系统空间预留，保守预算含所选内容、核心准备、替换下载和必要暂存；发布前重新核对来源与目标，不接受预览后新出现的同名实例。副本执行：准备独立核心 → 准备选中内容的候选 → 应用已确认设置和模组替换 → 完整校验 → 发布 → 验证 → 记录终态，一个父任务贯穿。取消只在既有安全点生效，提交/改名的短临界区不随意打断；相关实例占用与游戏根切换保护覆盖扫描完成到提交收尾。
- **历史与恢复**：复用现有事务 ID 和报告协议，扩充必要字段及读取兼容，不平行创建另一份账本。建议游戏根内的事务/报告为权威记录，记录来源和目标稳定身份，两边历史从同一事务检索；若必须两边各存一份索引，索引只引用同一权威事务，需幂等补写与可见的待修复状态，记录失败不能只留一个成功提示。快照显示归属对象及版本，恢复前核对目标，不默认删除新实例。成功/失败/取消/未处理按实际阶段记录；继续操作只重试计划允许的未完成部分，目标被外部改动就重新预览，不自动运行安装器。
- 新文件创建前查重，状态跟随页面/控制器的所有权，不继续扩大 `InstanceSettingsDialog` 和 `MainWindow`。
