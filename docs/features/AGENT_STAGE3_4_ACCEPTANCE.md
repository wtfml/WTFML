自动化能覆盖的部分已经跑过，结果见 [AGENT_STAGE4](AGENT_STAGE4.md)：core 15/15、window 3/3、network 6/6、ci-ui 23/23，智能体三套件全绿（`verify_agent` 767 / `ui_check_agent` 77 / `mw_check_agent` 76），`tools/check-agent-release.ps1` PASS。

下面条目按"现在还需要什么"分三档：

- **[半自动]**：自动化覆盖了判据，真机部分（真实网络/真实实例/真实用户）没做；
- **[人工]**：只能真机执行。

视觉套件（label `visual`）本轮未跑，属 **[人工]**。

## 0.1 怎么记

## G3：Stage 3 验收（联网与固定诊断命令）

### 3.1 联网地址策略

| # | 做什么 | 期望 |
| --- | --- | --- |
| [已自动] G3-1 | 让模型抓 `file:///C:/Windows/win.ini`、`data:text/plain,x`、`ftp://example.com` | 三个都被拒，理由是 scheme；没有网络请求 |
| [已自动] G3-2 | 抓 `http://127.0.0.1:8080/`、`http://localhost/`、`http://[::1]/` | 全被拒，理由写明 loopback |
| [已自动] G3-3 | 抓 `http://10.0.0.1/`、`http://192.168.1.1/`、`http://172.20.0.1/`、`http://169.254.1.1/` | 全被拒，理由写明 private / link-local |
| [半自动] G3-4 | 用一个同时有公网与内网 A 记录的域名（或 `nip.io` 形式，例如 `10-0-0-1.nip.io`） | 整条拒绝，理由指出是哪个地址、哪一档 |
| [半自动] G3-5 | 抓一个会 302 到 `http://192.168.1.1/` 的公网地址（可自建跳转） | 第二跳被拒；日志里能看到第二跳重新解析过 |
| [半自动] G3-6 | 抓一个正常 https 站点 | 工具卡显示 host、HTTP 状态、大小；结果是纯文本、没有 `<script>` 残留 |
| [已自动] G3-7 | 抓一张图片或一个 zip（`image/png`、`application/octet-stream`） | 被拒，理由写 Content-Type |
| [已自动] G3-8 | 抓一个大于 2 MB 的页面 | 结果 `truncated=true`，界面提示已截断 |
| [已自动] G3-9 | 页面正文里故意放 `token=sk-...`、`password=...` | 结果里被遮成 `<redacted>` |
| [人工] G3-10 | 系统里配置 HTTP 代理（或环境变量 `HTTPS_PROXY`）后再抓一次 | 仍然直连；抓包/代理日志里没有这次请求 |
| [人工] G3-11 | 抓一个证书主机名不匹配的 https 地址（例如把 IP 当 host） | TLS 校验失败，工具报错，不静默降级 |
| [人工] G3-12 | 对同一域名连续抓两次，期间改本机 hosts/自定义 DNS 让它指到内网 | 第二次拒绝（每跳都重新解析，不复用旧结果） |
