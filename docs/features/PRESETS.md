# 实例预设

给改预设、安装页预设选择弹窗和模组管理页的人看：预设怎么创建和使用、编辑器与草稿规则、安装时怎么选、模组执行的保护与恢复、模组操作栏的交互约定。

预设用于用户明确确认的初始化，启动时不会自动恢复配置或补回被删的模组。

## 1. 创建与使用

预设分五类，每类独立：游戏设置、模组、资源包、数据包、光影包（代码 `PresetCategory`：`GameSettings`/`Mods`/`ResourcePacks`/`DataPacks`/`ShaderPacks`，另有 `Unset` 表示没写类别的旧版混合预设）。`ResourcePacks` 兼容旧格式里一并保存的光影包。

1. 「管理 → 预设」按类别新建，直接打开空白编辑器（见 §2）。
2. 游戏设置点「编辑游戏设置与按键」，可添加视角、界面尺寸、自动跳跃、渲染距离和按键。视角用角度编辑（内部仍存原版归一化数值），界面尺寸显示"自动"，自动跳跃选开/关。也可从已有实例提取；其它服务器、MaLiLib 与配置文件段保留原有提取/应用能力。
3. 模组点「编辑模组清单」，粘贴 Modrinth 模组网页链接或填项目 ID，设置必要/可选。重复添加会定位原行；CurseForge 需使用数字项目 ID（网页 slug 存在变更可能）。限定版本/加载器留空表示跟随目标实例；不匹配时不下载其它游戏版本凑数。
4. 从实例提取成草稿时，本地 jar 先按 sha1 问 Modrinth，没认出来的再按 CurseForge 文件指纹（murmur2，剔空白）批量问；两家都认得的跟 Modrinth 走。两家都没认出来的行留成「未知来源（请选择）」，由人工补平台和项目 ID，或暂时关掉模组部分。该页有「只看没认出来的」（只藏不删，取消勾选都回来）和「移除没认出来的」（整批删，不碰已认出的行；整个编辑点「取消」仍能撤回）。
5. 下载游戏时，在加载器列表下的「预设」行按类别选择（见 §3）。先完成游戏及加载器，再处理预设；模组步骤属于原安装任务，可从任务中心取消。基础实例装好但预设失败会保留实例并说明部分应用。
6. 也可在预设管理中选目标实例，先预览再应用。平台模组的具体发行文件在执行时联网解析。

资源包/光影从已有实例提取；数据包按世界处理，没有目标世界时保留为待应用，不创建世界。

**数据包换包事务**：换掉同名那一份时先拷到旁边暂存、再两段改名。每一步之前在目标旁落一份登记 `.wtfml-txn-<目标标记>.json`；进程被杀后，下一次碰到这个目录（采集或应用）按登记收尾：目标还没换走就收掉暂存；目标已挪走就把原件放回；新内容已发布就收掉旧的。登记读不懂、或残骸没有登记 ⇒ 一个字节都不动，保留现场并提示人工检查，不凭文件名前缀删除或归位。换包期间的实例目录锁与「游戏在跑就不动手」检查由应用入口负责。

**默认项**：每类各一个，在预设管理里选中一份后点「设为默认」只影响它自己那一类，混在别的类里那一份不会被换下来。旧版本唯一的默认项照旧读、照旧写回，但不自动迁移成按类组合：它只在自己那一类还没表过态时顶上来，别的类不会被它点亮；若它是旧版混合预设（没有类别），一类都不推导。默认项被删或读不回来时，那一类就是没有默认（不偷偷换成同类下一份），安装页对应栏回到「不使用」。安装页记住的是"用户亲手改过这一栏"：没动过的类，以后设了默认会自动选上；亲手改成「不使用」的类，不会被后来的默认顶上来。

管理列表支持按名称或说明搜索，清空恢复列表。「从实例提取」默认折叠，展开后只显示当前类别允许提取的选项。「更新当前预设」替换对应内容，「提取为新预设」保留当前这一份。

## 2. 预设工作区（编辑器）

- 新建直接开空白编辑器，不先建一份可安装的空预设。左侧为概览、游戏选项、按键、模组、资源包、数据包，编辑期间不分页面写盘。
- 概览编辑名称、图标和启用部分；部分禁用后仍保留内容。类型按已启用且非空的类别计算。
- 左下角：保存为草稿、保存为预设、恢复到上次、全部清空。恢复/清空会丢失编辑，需确认；清空保留名称和图标。
- 返回、顶端导航和窗口关闭走统一离开检查：保存为草稿、保存为预设、不保存、取消。保存/校验失败留在编辑器。
- 草稿放 `presets/drafts/<id>`，不参与安装候选；已发布预设保存草稿不会覆盖可用版本。
- 资源包支持启用和顺序编辑，保留未涉及的现有包；缺少启用记录不自动改成全部开启。
- 实例维护的「另存为预设」提取到草稿再进编辑器；不提取模组配置和模组专有按键。
- 已启用本地模组按 SHA-1 分批查 Modrinth 身份，每批最多 100 项，串行，总截止 45 秒；未识别项保留待整理，不冒充兼容项目。
- 提取、资源复制和保存在后台。资源导入用带内容摘要的文件名；已存在但内容不同的目标拒绝覆盖。
- 游戏选项与按键直接列出可选项目，每项独立勾选是否纳入预设，空白预设不自动加默认值。选项覆盖画面、操作、辅助功能、聊天和声音（开关下拉框、枚举、整数和百分比控件），搜索支持中文名称、类别和原始键名。原版按键覆盖移动、交互、鼠标和快捷栏：点击控件录入，Esc 取消，退格清除，保存为 Minecraft 按键标识，不存 Qt 快捷键文本。控件目录见 `ui/PresetOptionCatalog.hpp`。
- 导入的未知选项和超出控件范围的值保留原文并可编辑，打开页面不静默截断；未勾选的项保留编辑值但不写入文档。
- 管理页嵌入：管理页明确设为 `Qt::Widget`（否则会弹独立窗口）并拦截继承自对话框的 Escape/Enter 关闭；预设模式收起整栏并恢复客户端模式侧栏；分类按钮固定两列、24 像素高。
- 旧预设中多段同类内容的编辑迁移：拒绝隐式合并，保留原件并提示从实例另提草稿，避免改变覆盖次序。

**数据与兼容**：运行时的 `sections` 和 `modReferences` 只含启用部分，禁用内容留在 `editorState`；旧加载器忽略编辑字段，只读运行时清单。草稿和编辑文档不直接作为安装指令，编辑器复用原有应用计划、兼容性检查、备份和执行报告。

### 综合预设的内部投影

综合预设只显示一份公共记录。一次发布把它拆成 `internalComponent` 子项（类别键 → 子项 id），只供安装页按类别单独选择，不出现在预设列表。重新发布时子项整批换新，旧子项失去唯一引用。

回收「先核对、再动手」：`orphanComponentIds()` 读全部 manifest 与 `index.json`，引用来源是任何一份可读 manifest 的 `editorState.components`、旧版单默认项、各类默认项。只有**读得懂所有相关文件**时才给候选；任何一份 manifest 或下标读不回来，这一趟一份都不回收。下标 `order` 里出现过的 id 一律留下，不替用户改下标。`saveEditorDocument()` 发布成功后和 `remove()` 删除后各跑一次；发布失败时只收掉这一趟刚创建、还没有父清单引用的子项（`discardInternalComponent()`），旧预设与旧子项不动。回收和普通删除同一条：先取目录锁，再 `moveToRecycleBin()`，不追链接。

## 3. 安装时选预设

安装页的「预设」行打开选择弹窗（`ui/PresetInstallPicker`，由 `InstallPageController` 接线；弹窗只维护本次选择，读取、兼容检查、安装由控制器负责）。弹窗只读取已有预设，本次选择不反向修改预设；预设的创建和编辑属于「管理 → 预设」。服务端安装不接预设。

**布局**：左侧分类导航（游戏设置、模组、资源包、数据包、光影包、综合预设）＋ 右侧可搜索的紧凑候选列表 ＋ 底部一行：左边「本次应用」摘要（「本次应用 N 类」，有缺失 / 未检查才补「· 缺失 X 项 / · 待确认 Y 项」；一类都没选写「本次不应用预设」），右边取消 / 确定。导航负责切换列表，不直接选预设；类别旁显示数量，这一类本次已选时数量旁多一个小圆点，综合预设不重复计数。「不使用」「管理预设」「兼容性详情」为固定入口。每页底部隔一道细线写「已选：xx」和「兼容性详情」。某一类一个预设都没有时，右侧居中写图标 + 「暂无可用的…预设」+「管理预设」；综合预设为空时多一句它是什么、去哪儿建。数据未读好时右侧显示统一的读取态（`beginLoading()` / `failLoading()`，`setCategories` 收尾）。

**列表项**：图标、名称、类型、内容数量（来自清单摘要）、兼容性状态、是否选中。单类别页底部有「显示综合预设」开关：关闭后只显示该类别的单一类别预设，只影响候选显示，不改应用规则；综合预设仍在「综合预设」分类中。

**综合预设规则**
- 同一份综合预设在「综合预设」分类和它包含的各类别里指向同一份数据，不复制。
- 在单类别（如「模组」）里选综合预设，只应用其中对应部分，不会应用其它类别。
- 在「综合预设」入口选择，可在页底「应用其中：」那排可选胶囊里挑本次应用哪些部分：有内容且有效的部分默认勾选，没内容的置灰；取消勾选只影响本次安装。预设作者在概览中停用的部分不算默认有效内容。
- 综合预设只提交有内容的所选部分；取消其中一部分，不会清除后来独立替换的其它来源。

**单类别冲突**：每个类别本次只有一个最终来源，不自动合并。选新预设时做类别级替换：只替换该类别当前来源，其它类别不变；替换前就地确认，明确说明替换的是哪个类别（如「替换模组：日常生存 → 建筑辅助」），取消不改变原选择。底部摘要始终显示各类别的最终来源，同一综合预设的多个部分可在多个类别里出现同一名称。

**兼容性状态**：已匹配 / 存在缺失 / 存在冲突 / 未检查 / 检查失败。「未发现问题」不等于「已确认兼容」；不凭文件名判兼容，须结合目标版本、加载器、模组元数据与依赖判定，未核实项显示未知或待检查。详情在独立只读窗口（已匹配、有更新、无匹配版本、加载器不匹配、缺依赖、无法确认），主弹窗不展开长明细。

**检查时机**：打开弹窗先读元数据和已缓存的检查结果，先显示名称、类别、数量；未检查或缓存失效的在后台检查；选中某预设后再做与目标版本、加载器相关的深入检查；目标版本或加载器改变后结果失效重验；检查期间界面保持可操作，逐项显示进度与失败。缓存必须关联目标版本、加载器和预设内容版本。

**资源包顺序**：预设保存资源包顺序，应用时按顺序处理预设涉及的包；只处理预设明确涉及的包，不删除用户现有的其它包；与现有内容重名或冲突要在应用前提示；最终顺序在安装预览中可核对。

**状态与限制**
- 纯原版及仅 OptiFine 不可选模组部分；真正应用前还会检查实例实际加载器。
- 光影包新建和发布使用独立类别；旧资源包/综合预设保持原始范围，读取不改写；旧停用状态在编辑转换中保留。
- 当前类别没有预设时显示「去管理预设创建，或从已有实例另存为预设」，不显示空白卡片或示例预设。只有草稿等于没有可应用预设。预设读取失败显示名称（若可读）、原因和重试入口，不静默忽略。检查失败保留选择并明确标出，不等同于兼容。
- 取消不提交本次选择。确认只把选择交回安装流程，仍经既有预检查、备份与安装后执行；提交前验证预设仍存在且版本未变，变化则刷新检查并提示。
- 不纳入：服务端预设、模组配置文件、模组专有按键和设置、同类多份自动合并、弹窗内编辑预设、复杂兼容性修复。

**设计遗留（实现是否已定案未核对）**：作者停用的类别能否在本次临时重新启用；「显示综合预设」是否记忆上次选择（首版固定默认开）；缺失/冲突是否阻止确认（倾向允许确认、由安装流程决定阻断项）；是否允许确认前逐个排除某个模组/资源包（首版只做预设级选择）。

## 4. 模组执行保护

### 已安装模组与依赖

预设安装先在后台扫描当前 `mods` 顶层的启用 JAR，不遍历其它目录；禁用文件不满足启用依赖。识别缓存、安装记录都要与当前文件 SHA-1 对上，不能凭文件名或缓存时间认版本；也用本次平台答复中的文件哈希确认改过名字的文件。项目、发行版和依赖元数据分别判定，重复项目或精确版本冲突不自动覆盖。已安装父模组仍展开自身必要前置，只补缺失项。

写入前后台重核文件清单；增删或内容变化会中止并要求刷新。失败、取消保留旧身份记录。实例目录被外部删除时不重建；执行器销毁会取消后台扫描。可选项身份未确认只记为可选失败，不阻止已确认安全的必要项；同一内容对应多个项目/发行版时不采用先返回的答案。扫描限 10000 个 JAR、每 1 MiB 检查取消，整项 600 秒预算。

未确认的文件通过 Modrinth `POST /version_files` 查实际 SHA-1 对应的发行版：每批最多 100 个哈希、顺序去重，沿用整项 600 秒预算；不用「查询最新更新」接口。响应必须包含匹配的文件哈希、项目及发行版身份，再检查目标游戏版本、加载器与精确依赖。已确认的其它平台身份不被 Modrinth 答复覆盖；已有 Modrinth 记录与答复冲突时拒绝自动改写。无结果、限流、损坏响应和取消都不证明文件不存在，仍显示身份未知。其它平台的已安装文件哈希/指纹反查尚未接入（与下面"只有发行版 ID 的前置反查"是两件事）。缺失项目可在下载前确认页明确填写本次替代，重新检查替代项目和全部必要前置后再确认；未知状态不能靠填写替代放行，已有冲突文件不自动覆盖。

- 复用资源平台取数与生产下载器；顺序查询并去重，必要前置最多 256 个项目，整项最长 600 秒。
- 平台明确没有发行版与网络未知分开；必要项未解决时不写入模组。
- Modrinth 必要前置只有发行版 ID 时，先用官方 `GET /version/{id}` 确认项目身份，再按原有游戏版本、加载器、文件哈希和精确约束检查，不以最新版替代指定发行版。单次操作去重，最多 256 个，沿用网络超时及整项 600 秒取消预算；响应身份不符、字段缺失或查询失败显示原因，不写入依赖未确认的模组。CurseForge 仅文件 ID 的前置走批量文件反查，必须返回唯一、匹配的文件 ID 及所属项目；错误身份、鉴权失败和损坏响应都不能满足前置。
- 必要文件全部通过大小/SHA-1 检查后才进写入阶段；不接受无可信 SHA-1 的远端模组。
- 文件名只接受安全 JAR 基名，拒绝路径穿越、危险目录链接和同名内容冲突；已有文件不覆盖。
- 可选依赖失败时保守跳过可选下载项，不留下已知缺前置的可选模组。
- 精确依赖按平台发行列表里的版本 ID 筛选；互斥约束和缺项目 ID 的版本专属依赖安全阻止。计划层合并多父项精确版本约束，在原候选集合里选匹配发行版；不同父项钉住同一前置的不同发行版时汇总冲突，有效循环去重，不能收敛的明确阻止；只有发行版 ID 没有项目 ID 的必要前置显示"暂无法确认"。`installedKeys` 只证明项目存在，精确约束还须 `installedVersionIds` 提供平台发行版 ID，未知或不匹配不得视作满足；没有身份的已安装文件不能当作满足前置。可选前置只列出、不自动加入；必要前置失败沿父项传播，不牵连其它独立可选分支。
- 中途写盘错误如实报告已写入数量，不声称全量回滚。
- 执行记录原子保存到实例 `wtfml.preset-mod-install.json`：版本/加载器、所选预设内容快照、计划文件身份、成功/取消/部分失败状态。`plannedFiles` 只是计划。

### 查询、确认与恢复

预检查先做本地判定，再查进程内缓存和平台；最多 4 项在途、单项 12 秒、整轮最多 600 秒。新一代查询、超时、取消和对象销毁都会真正取消请求及后续退避。缓存按平台/项目、游戏、加载器、运行侧、发布筛选、数据版本、接口根和凭据摘要区分，只缓存明确匹配/缺失；格式损坏、元数据缺失、未取完分页均为暂无法确认。CurseForge 预检查与资源页同一来源设置：有自有 key 走官方，否则用配置的公共镜像。

最终确认列出具体发行版、文件、大小、前置、冲突和替代差异。替代仅本次有效，不改写预设；拒绝/关闭即取消，必要项未解决不能进入下载。跨预设引用去重后只执行本次实际选择，下载前和部署前重新核对所选预设内容及目标，内容变化要求重新预览。

同一实例的预设应用持有专用写锁。必要下载先全部校验，再按前置优先顺序部署；每个文件原子提交，文件之间让出界面并可取消，已提交项保留，不宣称整趟回滚。模组报告逐项区分 planned/downloaded/enabled/skipped/blocked，并记录原项目→替代项目；下载前、部署前、每个文件提交后及终态都原子保存，写报告失败会停止后续部署。

暂存：模组暂存文件按 SHA-1 保留在实例 `.wtfml-preset-downloads`，同内容去重，恢复仍完整校验。任务中心可暂停文件阶段；关闭重开先补齐，再明确继续才重新检查清单/目标/兼容并部署。过期地址由重新查询解决，替代授权不跨次保存；实例被外部移走时拒绝重建。部署阶段不开放暂停。

本地预设报告（设置等）保存为实例 `wtfml.preset-apply.json`：计划完成且覆盖获确认后才建报告/备份，记录各段实际写入、移除、失败和待应用数量。预设页有「执行报告」和「继续未完成」（需再点击确认，重启后仍可用）。本地段恢复校验实例根、预设指纹和逐项状态，只重试未完成段；模组恢复重新核对完整选择与实际 SHA-1，已落盘项不重复下载。源预设改变、损坏/不匹配的报告不能自动恢复。没有世界的数据包标为 pending-world，继续时重新检查目标世界，不创建世界。部分应用不新增启动门禁，但会警告并保留实例、已写入项和备份。报告每实例只留最近一次。

## 5. 模组操作栏

模组管理页（`ui/InstanceFilesPage*`，选择与操作栏内联在 `ui/InstanceFilesSelection.cpp`，关闭按钮 `modActionPanelClose`）的交互约定。原稿在仓库上一级《其余的一些设计.md》；以下以用户接受的修正为准，早期"混选隐藏启用/禁用""成功一律收起"已作废。首版只做模组页，资源包/数据包/光影页保留原布局。

**布局与选择**
- 左侧保留实例导航，中间宽列表，右侧操作栏宽窗为 156 逻辑像素，单列图标与文字；无选择时收起，选择后从右侧展开，不全局常驻、不遮挡顶部导航。内容宽度不足 740px 时改为 56 逻辑像素的单列图标栏，以悬浮提示显示名称；两种宽度都给列表让出空间。
- 列表顶部选择工具行：`共 N 个模组，已选 M 项    全选 / 反选 / 清除选择`；无选择时隐藏已选数量、禁用清除。全选/反选只针对当前筛选结果，筛选隐藏的项退出选择，不暗中扩大范围，页面明确提示。
- 选择工具行与状态筛选胶囊同排还是另起一行，只看页宽：按「全部 / 启用 / 禁用 / 可更新」四颗胶囊和「已选 M 项」都露出时的宽度判断。启用、禁用某项让胶囊增减时排法不变，列表不上下跳。
- 删除动作使用可读的危险色；不可用按钮使用弱化文字与图标、透明底和虚线边框，随主题更新。
- 拖出文件时保留拖拽前选择和滚动位置，鼠标按住期间列表继续重绘。
- 右栏 × 只收起、不清选择；点列表顶部「已选 M 项」重新展开；选择变化自动展开。开合用统一合成快照动画。
- 启用/禁用、检查更新、复制成功后保留选择和面板；失败保留。删除/移动成功只移除实际处理成功的条目。文件改名刷新按稳定身份保留选择；切换实例清理旧上下文，异步返回不得修改另一实例。

**操作层级**
1. 状态：「启用」「禁用」独立按钮；已达目标状态时禁用对应命令。
2. 进入模组页自动只读检查更新，跳过禁用文件；全部检查完成后，有失败或无法确认项时在任务中心汇总一条「更新检查结果可能不完整」，具体原因保留在详情中；同一实例连续产生相同结果时不重复通知。不弹窗或跳转。实际更新先展示待更新清单，二次确认后执行。
3. 复制到实例 / 移动到实例：明确区分保留或删除来源；移动只在目标校验成功且源未改变后才删源。
4. 删除独立展示并确认；只删模组文件，不附带「同时删除配置」。配置清理将来另做归属预览，不能因删某个模组就删共享配置目录。
5. 更多：详情、文件位置、依赖与冲突、项目网页（用已识别平台与项目 slug，未知资源不猜链接）、导出列表（复制模组清单），以及低频「反转每项启用状态」（每项独立翻转，不按第一项决定整批）。不支持的能力不伪装成成功。
- 固定面板、自动清理、测试实例/二分排查属于后续规划功能。

**更新确认**：只读、可滚动、可复制的清单，显示当前版本 → 目标版本、新增/移除声明、类型和固定版本变化；显示目标版本、文件名、游戏版本及加载器，仅提交清单内可更新项。移除声明不删现有模组，确认也不自动补装依赖。确认期间检测目标或本地文件状态（大小/修改时间快照）变化则中止并要求重新预览。沿用原回滚/下载执行器。文件哈希/指纹反查保留当前版本元数据；已知空依赖与未返回依赖资料分开，未知、重复或字段不完整不显示"无变化"；项目名称未知时显示项目号。根据同平台、启用且仍存在的已识别项目和本批目标版本提示必需依赖版本不符、明确不兼容；未识别只提示需确认。CurseForge 依赖按[官方 API](https://docs.curseforge.com/rest-api/)保留必需/可选/不兼容/内嵌语义。当前不包含全局依赖求解器。

**依赖与冲突检查**：更多菜单「依赖与冲突」只读检查当前选择，报告可滚动、可复制，不安装、删除或修改模组。读取按文件大小/修改时间验证的身份缓存，不算哈希、不联网、不写缓存；旧缓存缺依赖资料标未知。仅同平台、当前启用的已识别项目参与判断，禁用项只展示声明；固定版本不符、明确不兼容、重复启用项目分别提示。不解析 JAR 内版本范围，不做跨平台身份映射。

**复制/移动执行**：分块复制与双侧 SHA-256 校验在工作线程，UI 定时读进度；任务中心和提示都显示当前文件与已处理数并能请求取消。源、目标接入实例忙状态（阻止启动/删除/重新打开设置，当前设置页执行期间禁用）；运行/安装中的实例拒绝处理。临时文件放目标 mods 内，校验后独占改名提交，不覆盖同名（含启用/禁用别名），失败/取消自动清理；Windows 下临时文件提交方式已专门处理。取消按分块/校验边界响应，合作式总截止 600 秒，已完成项保留，未完成的移动不删源；发布后取消导致两份均保留时，重复操作仍跳过已有目标，不擅自删来源。不处理配置。

**统一文件操作报告**：批量启用/禁用、批量删除、单文件复制的结果走 `OperationReport`：逐项状态、失败原因和「共 N 项：完成 / 跳过 / 失败」只有一套说法，有失败时另写 `<报告>.failure.txt`。拖入同名文件提供「取消」（停掉同批剩余）「跳过已有项」「盖掉」三档；世界导入没有「盖掉」。任务中心只展示父任务，报告仍可续时出现「继续未完成操作」。

从主窗口拖入模组时，目标选择器批量读取归档中的模组声明，复用实例升级的版本规则。目标实例的 Minecraft 版本或加载器明确不符时，行内显示原因，用户仍可选择该实例。无法读取版本范围的文件仍可手动安装。

**待增强**：完整依赖求解、变更日志与二进制差异、跨版本自动下载适配模组、多 DPI/大量条目实机验收；整体实例迁移/升级见 [INSTANCE_UPGRADE.md](INSTANCE_UPGRADE.md) 与[主计划](../ROADMAP.md)。
