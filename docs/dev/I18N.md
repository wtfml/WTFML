# 界面多语言（英文）交接

给维护英文界面的开发者，说明翻译加载、文案抽取、译文和验证流程。

## 1. 现在到什么程度

- 源语言是中文，代码里的字面量就是简中界面。**zh_CN 不装翻译**，直接用源文。
- 英文是译文：`assets/i18n/wtfml_en.ts` →（lrelease）→ `wtfml_en.qm` → 编进 exe 资源 `:/i18n/wtfml_en.qm`。
- 英文目录共 **6894 条**，均有译文。覆盖主页、账号与皮肤、世界设置、下载和整合包导入、
  模组预设、主题、服务器列表、信标计算、测速和回放信息等场景。
- **英文译文待精修**。待统一 Minecraft 术语与界面用词，并逐页校对英文提示、按钮和长文案。
- `tools/i18n-baseline.txt` 记录尚未抽取的中文候选；它还包含内部日志、协议文本和测量样例。
  逐条判断用途，界面文案接入翻译，内部文字保留原文，不增加基线。

## 2. 运行期怎么选语言

`ui/UiLanguage.hpp` 是唯一出处。

- 设置键 `General/Language`，取值 `system` / `zh_CN` / `en`。首次启动和设置页共用
  `UiLanguage::readSetting()`，缺省或无法识别的值均按 `system` 处理。
- `resolve(设置值, QLocale::system().uiLanguages())` 直接采用 `zh_CN` 或 `en` 的显式选择。
  `system` 检查系统 UI 语言表，含中文时用 `zh_CN`，其余用 `en`。
- `installTranslation()` 在 `src/main.cpp` 里调用一次：**验收档案建好之后、任何界面创建之前**
  （档案那一步会把 `QSettings` 指到隔离目录）。`zh_CN` 什么都不做；资源里没有 `.qm` 时记一句
  警告、界面退回中文。
- 改语言不即时生效：设置页弹提示卡「已保存为当前选择，重启启动器后生效」，两颗按钮
  「立即重启」「稍后」。`MainWindow::onLanguageChanged()` 里先 `DirectorySessionLock::releaseAll()`
  再 `QProcess::startDetached`（参数照抄本进程，`--acceptance-profile` 也在其中），最后 `quit()`；
  新进程起不来就重新取回目录锁并报「重启失败」。
- 目录锁的语义（同一游戏文件夹只允许一个窗口）见
  [DIRECTORY_SESSION_LOCK.md](../features/DIRECTORY_SESSION_LOCK.md)。

## 3. 构建管线

- CMake 里那一段在文件开头（`WTFML_I18N`）：`assets/i18n/wtfml_en.ts` → lrelease →
  `<构建目录>/i18n/wtfml_en.qm`；`wtfml_embed_translations(<target>)` 用 `qt_add_resources`
  把它按 `PREFIX /i18n` 编进目标。产品挂一次；要验英文界面的验证工程再挂一次（`ui_check`）。
- lrelease 从哪儿来，优先级：
  1. `-DWTFML_LRELEASE=<lrelease.exe 的完整路径>`；
  2. Qt6LinguistTools 提供的 `Qt6::lrelease`（动态 Qt 自带）；
  3. 自动找：当前 Qt 的 `bin`（按 `Qt6::qmake` 的位置推）、`QTDIR`、本机动态 Qt
     `D:/Qt/Qt/6.10.1/mingw_64/bin`。
- 三个都没有 → **配置阶段 FATAL_ERROR**。唯一跳过办法是显式 `-DWTFML_I18N=OFF`，那一份产物
  没有英文界面。
- 静态 Qt（`D:/Qt/static-6.10.1-mingw13/install`）只编了 qtbase，没有 LinguistTools，走第 3 条
  命中动态 Qt 那份 lrelease；`.qm` 编进 exe，静态单文件版不依赖外部文件。
- 只改 `.ts` 时不用重新配置，直接构建即可（lrelease 那一步会重跑）。

## 4. 怎么包字符串

- 有 `Q_OBJECT` 的类里：`tr("源文")`。
- `ui/` 里的界面类多半不是 `QObject`（`ui/` 不许 include `src/`），那里一律
  `QCoreApplication::translate("MainWindowUI", "源文")`。
- 上下文就是类名 / 模块名。同一个词有两种意思时才另起上下文；别每个文件发明一个新上下文，
  翻译表会碎成一片。
- 只存不翻、用的时候再翻：`QT_TR_NOOP("源文")`。
- 带参数的用 `tr("%1 个").arg(n)`，占位符 `%1` 原样保留。
- 预设的 Minecraft 配置键、按键标识和选项值存原值。将显示标签作为独立字符串翻译。
- 不该翻的（日志、内部提示词、语言名自身）在行尾标 `// i18n-ignore`，整行不计入守卫。
- 新加的**用户可见中文**必须当场包起来，否则 `check-i18n` 直接红。

## 5. 刷新 .ts、写译文

```powershell
pwsh tools/i18n-update.ps1                    # 用本机动态 Qt 的 lupdate
pwsh tools/i18n-update.ps1 -Lupdate <路径>    # 或者自己指
```

它执行 `lupdate -locations none -no-obsolete src ui -ts assets/i18n/wtfml_en.ts`：新条目是
`type="unfinished"`，已有译文保留，源码里删掉的条目一并清掉。随后更新 `assets/i18n/wtfml_zh-CN.ts`。
这个中文源目录只供 Crowdin 使用，保留 Qt 上下文和源文，清空译文。仅重生成源目录可加 `-CrowdinSourceOnly`。

- 译文用 Qt Linguist 打开 `assets/i18n/wtfml_en.ts` 填；也可以直接改 XML 里的 `<translation>`。
- 没翻的条目照样出 `.qm`（lrelease 只报个数），英文界面里显示源文中文。
- 界面术语见 [UI_COPY](UI_COPY.md)，游戏规则标签沿用 Minecraft 的规则术语。

### 用 Crowdin 校对

1. 在 Crowdin 建文件型项目，源语言选简体中文，目标语言选英语（美国）。开启占位符和标签检查，关注 Qt 的 `%1`、`%L1` 和 `%n`。
2. 在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 添加仓库变量 `CROWDIN_PROJECT_ID` 和 `CROWDIN_MODE`，将 Crowdin 访问令牌存为仓库密钥 `CROWDIN_PERSONAL_TOKEN`。令牌需要读取项目、读写源文件和译文的权限，并且持有人需要是项目管理员。同步 PR 需要组织策略允许该仓库的 GitHub Actions 创建 PR。
3. 首次将 `CROWDIN_MODE` 设为 `seed`，推送 `i18n-phase1`。工作流上传中文源目录和现有英文译文，导入的译文保留待审核状态。成功后把变量改为 `sync`，后续分支推送会同步源文并拉取英文译文。工作流进入默认分支后，也可以在 Actions 里手动选择 `i18n-phase1` 运行。
4. Crowdin 有新译文时，工作流检查 Qt 上下文、占位符和现有译文是否丢失，再为 `i18n-phase1` 提审校 PR。按 [界面术语表](UI_COPY.md) 校对，编译并运行英文界面巡检后合并。

在 Crowdin 项目的 **Settings → Glossaries** 中打开项目术语库，导入
[Minecraft 原版术语 CSV](../../assets/i18n/minecraft_terms.csv)。确认两个术语列对应 `zh-CN` 和
`en-US`，类别与语言键分别对应 Concept Subject 和 Concept Note。编辑器会在匹配的源文上显示术语提示。

配置在 `.github/crowdin.yml`，只同步 Qt TS 文件。译文回写到 `assets/i18n/wtfml_en.ts`，由普通推送创建审校分支。

## 6. 守卫与基线

```powershell
pwsh tools/check-i18n.ps1                  # 有文件比基线多就失败（CI 的 repo-rules 会跑）
pwsh tools/check-i18n.ps1 -UpdateBaseline  # 包完一批字符串之后把基线改小
pwsh tools/check-i18n.ps1 -SelfTest        # 验守卫自己那几条判据
```

- 判据：`src/` 与 `ui/` 的 `.cpp/.hpp/.h` 里，字符串字面量含汉字或全角标点、又不在
  `tr(` / `translate(` / `QT_TR_NOOP(` 这类包装调用的括号里，算一处。注释里的、`#include`
  后面的文件名、标了 `// i18n-ignore` 的行都不算。
- 基线格式 `路径<TAB>处数`，**只许减不许增**。包完字符串 → `-UpdateBaseline` → 数字变小 →
  提交里看得见降了多少。第 2 期目标是 0。
- `tools/check-test-modules.ps1` 另有一条：`tests/support/SettingsIsolation.hpp` 必须仍把界面
  语言钉成 `zh_CN`。

## 7. 怎么在英文下看效果

- 起真 exe 必须隔离：`--acceptance-profile <临时目录>`。目录里要有 `acceptance-profile.json`
  （`format` 是 `wtfml-startup-acceptance/1`，`closeAfterMs` 2–120 秒）；`tools/dev-run.ps1
  -AcceptanceProfile` 会建好这一份。
- 想让它自己走一遍语言切换：档案里加 `"languageStep": "en"`。程序会切到设置页、拍「语言」那
  一行、真改一次下拉框、拍提示卡、点「立即重启」（`src/util/StartupAcceptance.hpp`）。新进程带
  同一个档案起来，再拍一张。产物：`settings-language-<pid>.png`、`language-prompt-<pid>.png`、
  两个 pid 的 `startup-<pid>.json`。
- 想直接起英文：在档案的 `<root>/settings/WTFML/WTFML.ini` 里写

  ```ini
  [%General]
  Language=en
  ```

  `General/Language` 在 INI 里的写法就是 `[%General]` 段；顶格 `[General]` 放的是**无分组**的键。
- 逻辑宽度小于 1024 时导航轨只画图标。截图前设 `QT_ENABLE_HIGHDPI_SCALING=0`，否则窄屏机器上
  永远拍不到带文字的导航轨。
- 测试默认用 `zh_CN`。`wtfml.ui-language` 加载随程序编入的英文翻译，检查导航、主页按钮、
  世界难度、主题和预设配置值。单独运行可用 `ctest --preset verification -R '^wtfml\.ui-language$'`。

## 8. 界面大改后，受文字长短影响的地方（第 4 期重点看）

合入步骤 126–152 的界面大改之后，下面这些地方按中文的字宽 / 字数算尺寸，英文一进来就会变样。

- **字号区间**：`Theme::fitPixelSize`（`ui/Theme.cpp:209`）和 `ElidedLabel`（`ui/ElidedLabel.hpp:51-68`）
  在 `[lo, hi]` 里挑「放得下整段」的最大一号，到下限还放不下才省略。用到的三处：
  主页当前实例名（`ui/MainWindowUI.cpp:1942` 的 `setFitPixelRange`）、实例设置页页眉
  （`ui/InstanceSettingsDialog.cpp:214-216`，下限 20）、每日一言（`ui/MainWindowUI.cpp:998`）。
  英文句子比中文长，字号更容易压到下限，甚至出省略号。
- **紧凑页头状态胶囊**：`InstanceFilesPage::possibleStatePillsWidth()`（`ui/InstanceFilesSelection.cpp:386`）
  与 `placeCompactStateRow()`（同文件 :398，判据在 :403）：按「搜索框宽 + 胶囊总宽 + 24」决定胶囊
  摆在搜索框后面还是另起一行。英文的 State 文案更长，会有更多页掉到第二行 —— 看版面不跳、不压搜索框。
- **模组页操作栏等宽**：每颗按钮的下限按自己那两个字的字宽算（`ui/InstanceFilesPage.cpp:456`），
  「检查更新 / 删除」变成 Check updates / Delete 之后七颗加起来更宽，窄窗口下先被压的是左边那句
  「已选择 N 个文件」。
- **表头对齐**：`DesignDefaults::alignHeaderLabel()`（`ui/DesignDefaults.cpp:143`，从 `ui/Theme.cpp:905` 调）
  按表头文字算对齐，英文表头宽度不同，列头与内容要重新核对。
- **输入框量宽**：`InputSizing`（`ui/InputSizing.hpp`）按字符数加样例字量宽，样例串全是中文口径；
  英文界面下这些框要么偏窄要么偏宽。第 4 期给它一个按语言的样例档，或者在调用点多传一个样例。
- **设置页搜索**：`findSetting`（`ui/MainWindowSettingsPage.cpp:276`）拿 `settingsItemLabel` 那几行的
  **当前文字**做 contains，字包进 `tr()` 之后自动跟界面语言。第 2 期包完要复验英文下搜
  language / theme 能命中；不要另建一份中文关键词表（会跟译文漂开）。

跑法：清单用 `tests/ui_check/surface-registry.txt`，执行 `wtfml.surface-sweep`（`WTFML_SURFACE_SHOTS=<目录>`
出样张，`WTFML_SURFACE_THEME` 换主题，见 `docs/dev/TESTING.md`「表面登记」）。设置
`WTFML_SURFACE_LANGUAGE=en` 运行英文巡检。独立与合并测试程序都内嵌译文，显式要求英文但加载失败时退出并报错。

留给接手的人决定：主页问候语（`HomeGreetingLabel`，`ui/MainWindowUI.cpp:249`）和每日一言要不要跟界面
语言走。每日一言现在是中、日、英三个句子池随机取（`src/util/DailyQuote.hpp` + `Theme::QuoteScript`），
要跟界面语言走就得改取句逻辑，不只是翻译问题。

## 9. 已知限制与坑

- `check-i18n` 按行扫：块注释有跨行状态，跨行字符串字面量没有；`QStringLiteral(QString(...))`
  这种拼出来的串算「没包」。会多报，不会漏报，多报就标 `// i18n-ignore` 或换写法。
- 英文档未接入翻译的界面文字仍显示简体中文。
- 导航图标按**序号**认（`ui/TitleBar.cpp` 的 `iconForIndex()`），顺序契约就是 `MainWindowUI`
  那五个 `addTab` 的先后。加语言不用动它；**重排页面**要同步改，`ui_check` 有断言盯着
  「英文下五颗都有图标」。
- 「简体中文」「English」这两个选项名是各自语言里的写法，永远不翻。
- `lrelease` 不会因为 `.ts` 中还有 `unfinished` 条目而失败；提交之前检查新增条目和占位符。

| 期 | 内容 | 建议做法 |
| --- | --- | --- |
| 2 | 抽字符串：界面上能看到的包 `tr()`，只进日志的和智能体提示词标不翻，守卫基线降到 0 | 按目录分工，一个提交一个目录；每批跑 `-UpdateBaseline`，让基线一路往下降 |
| 3 | 术语表 + 全量英译 | 先补 `UI_COPY.md` 的英文对照列（Minecraft 用官方英文名），再逐条填 `.ts`；主脑抽查 |
| 4 | 英文版面巡检 | 清单就是 `tests/ui_check/surface-registry.txt`，配表面巡检 sweep（`wtfml.surface-sweep`，步骤 134）：中英各跑一遍、各出一套样张；截断、挤压交设计修。先看第 8 节那几处 |
| 5 | 智能体回答语言、每日一言只出英文句、README 截图换英文界面 | 依赖英文界面已经翻完 |
