## 7. 暂缓：条件与恢复方式

仅移出缺条件的子项，同条中可在代码侧推进的部分仍留在当前队列。

| 项目 | 当前边界 | 恢复条件 |
| --- | --- | --- |
| 正版登录真实全链（P1） | 尚无项目自己的 Azure App ID 和所需审核；构建时用 `WTFML_CLIENT_ID` 注入 | 应用注册/审核就绪，用户可完成授权 |
| Minecraft 登录令牌迁移到 Windows 凭据管理器 | Agent 改造不迁移；现有 `TokenStore`/DPAPI 保持 | 单独立项：多账号迁移/回滚/旧值兼容/跨用户边界设计与测试 |
| 额外系统缩放/辅助功能 | 已有 100%/125%/150% 基础采集；复杂新页面和系统减少动态效果需配合 | 用户可切换系统设置时补验 |
| Actions 缓存/分片实测 | 账单/额度影响未重新确认 | Actions 可运行后按真实记录测量 |
| 多网络/代理矩阵 | 缺第二网络或测试员新样本 | 有可控环境或新报告后对照 |
| 干净机器/低端 GPU 发布验收 | 本机软件渲染不等于完整驱动/部署覆盖；部署器提示缺可选 dxcompiler/dxil | 有对应机器后验证；不擅删依赖 |
| 正式更新通道 | 用户要求正版登录全链完成后再做 | 登录验收完成后确认发布与签名策略 |
| gzip/段错首因 | 缺可复现现场（2026-10-25 实例模块 gzip 夹具创建失败后级联段错，已加防护） | 保留旧证据，复现时定位，不持续空跑 |
| 工具箱独立窗口/搜索/彩蛋（P3） | 尚未确认产品范围 | 用户明确选择范围后实施 |

## 8. 约束与完成标准

- 当前行为以 [FEATURES](FEATURES.md) 与 [升级实现](features/INSTANCE_UPGRADE.md) 为准；升级新规范是待开发设计。
- 复制保留来源；原地升级先完整快照并可回滚。不得为新选择器放松哈希、路径或发布前外部修改检查。
- 不确定兼容性不得猜测为兼容；来源、目标、类别与具体加载器版本共同决定检查是否仍有效。
- 界面不加冗余说明，不用中点分隔文案；必要风险放在做选择和最终确认处。
- 游戏、原稿、历史失败和恢复材料不随计划清理删除；不使用真实存档做破坏性验证。
- 开发/准备任务设置独立截止，构建默认 300 秒、单程序不超过 900 秒；不以重跑覆盖首次失败。
- 代码修改跑受影响模块，文档修改检查引用；提交/推送、构建、真机与实网验收分别说明。
- 未验收不勾完成；未确认风险只记待核。
